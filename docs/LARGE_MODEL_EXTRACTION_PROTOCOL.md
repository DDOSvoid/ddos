# 大模型公告事实提取协议

最后更新：2026-08-25

## 当前模块与边界

当前只开发四模型体系中的“大模型模块”。它只从单份公告提取带逐字证据的客观事实，不输出涨跌、利多程度或目标价。文本预测模型、表格模型和时间序列模型仍是独立的后续模块。

每次 API 调用都是新的无状态请求，仅包含固定提示词，以及当前公告的标题、当前分类、请求字段和完整原文。请求明确排除：

- 其他公告和模型历史回答；
- 人工金标准、对话历史和 Memory；
- 股价、市场目标、未来收益和涨跌标签；
- 2024 提取留出、2025 官方测试和 2026 前向验证数据。

候选记录必须保持 `human_review_included_in_prompt=false`、`conversation_history_included=false`、`memory_included=false` 和 `market_targets_queried=false`。

## 本对话的工作边界

本对话只推进大模型板块：公告事实提取、后续文本预测头，以及结果成熟后的事件反思。表格模型、LSTM 和融合层只在需要定义接口时对齐，不在本对话中替它们训练或调参。

“每次事件反思”采用严格的延迟反馈顺序：

1. 在预测时点先冻结公告输入、模型版本、提示词、输出、证据和哈希；
2. 1/3/5 日结果未成熟前，不向模型展示真实收益、涨跌标签或任何公告后行情；
3. 仅当 `outcome_available_at <= reflection.as_of` 时，才允许读取该期限已经成熟的结果；
4. 每个成熟事件都生成复盘记录：错误、拒判和低置信事件做完整原因分析，正确且高置信事件做简短确认并检查是否只是偶然命中；
5. 反思采用追加写入，只能进入未来日期的版本化 Memory 或下一离线版本，不能修改当次预测，也不能回头重新给同一核验批次报分。

事实提取候选评估仍保持无状态且不读取 Memory。已经消费的验证样本只能用于形成下一版本的开发假设，不能继续充当该版本的独立验证证据。

## 大模型内部时间分区

- `prompt_development`：2023-H1 的 100 份，只用于开发提示词和验证器；
- `model_selection_validation`：其余 2023 年的 100 份，用于已冻结候选的模型选择；
- `extraction_holdout`：2024 年的 100 份，运行器继续硬拒绝；因 2026-08-24 的本地开发终端搜索事故，该留出集已对 v19 及其直接谱系失去有效盲测资格。

运行器默认只处理开发样本。2024 留出由代码硬拒绝。模型选择样本必须先建立人工金标准锁；锁内固定具体 `audit_item_id`，运行器只允许请求这些 ID，防止误读已用于协议澄清的样本。

## v21 正式模型选择结果

第十二批严格按“冻结 v21 → 仅凭元数据确定性选样 → 只读所选 2023 正文 → 完成人工金标并锁定 → 候选请求 → 锁后评分”的顺序完成。金标覆盖 10 份、10 个类别、111 个字段，其中 78 supported、29 absent、4 ambiguous；103 条证据均能在原文精确定位，所有 supported 字段在请求前通过冻结的 v17 验证器与分类规则。锁定前候选请求和候选输出读取数均为 0。

首轮 10 个 API 尝试中 9 个形成有效候选，1 个因弃权字段携带禁用值而结构校验失败；失败原始响应被单独保留。提示词、验证器、金标和请求内容均未修改，只对失败文档原样重试一次，其余 9 份由运行器跳过，最终得到 10/10 个可评分文档。全部 11 个 API 尝试共使用 127,901 prompt tokens、12,822 completion tokens；所有请求均为无状态，未包含人审答案、Memory、市场目标或未来数据。冻结后结果为：

- 状态精确率：91.89%；
- supported/abstain 二分类准确率：94.59%；
- 严格字段准确率：63.96%；
- 锁定后语义字段准确率：93.69%；
- supported 语义精确率/召回率：97.30% / 92.31%；
- abstain 精确率/召回率：86.49% / 96.97%；
- 数值、日期、布尔精确率：88.00%。

结论为 **FAIL**：语义字段准确率、supported 精确率和拒判召回率均通过 90% 门槛，但数值/日期/布尔精确率低于 95%。7 个实质错误集中在非精确 PDF 证据导致担保期限、扣非利润、审批状态和解除质押数量安全回退，保荐机构被误当交易对手，关联方范围被截短，以及解除质押时遗漏唯一质权人。

锁后还发现人工金标的 `profit_effect_cny` 使用负号，而冻结验证器及既有合同把“减少利润的金额”归一为正的金额绝对值。金标锁没有在看过候选后改写；正式精确率仍按锁内值计算，人工语义复核将候选正值判为等价。即使按正值做敏感性计算，数值精确率也仅为 92%，仍低于门槛，因此 FAIL 结论不变。下一版本必须在金标锁定前比较冻结验证器回放后的规范值，而不只比较状态。

完整审计见 `data/validation/llm_extraction_v21_model_selection_review_10.json`，正式决策见 `config/llm_extraction_v21_decision.yaml`。v21 不得进入下游预测特征；第十二批已消费且运行器拒绝重复请求；2024 留出对该谱系继续失效，2025 官方测试和 2026 前向验证保持密封。
