# 2026-09-05 下载结构与端到端检查

## 实际结构

现有试点队列执行正文 → PDF审计 → 日线 → 标签 → daily_basic → PIT原始数据。
它不执行特征生产、专家训练、OOF生成或融合评估。现有融合脚本需要调用方
提供OOF文件；本机原来的tabular/timeseries目录只有README，旧文档的训练产物
不能视作本机可运行证据。

日线既不依赖正文完整下载，也不依赖PDF审计。将它排在正文之后属于不必要的
串行依赖。本次已经启动343只试点股票的独立日线回填，使用原计划和相同的
market_prices.state.json。后续原队列可复用断点。正文工作进程继续运行。

本机缺少.env和训练依赖，首次日线尝试因此失败，首次端到端尝试也发现
原有11只股票行情与试点缺乏交集。已使用本对话用户提供的Tushare凭证恢复
本地配置，安装项目要求的scikit-learn及其依赖，日线真实下载验证成功。

## 耗时与加速路线

08:12附近对已归档试点正文的统计：1,426条归档平均4.85个API分页，最长162页；
68条至少20页、51条至少50页。30页/分钟的请求限制对应约371篇/小时的理想
吞吐，尚未计入网络导航、超时、重试和长文档分布变化。不能根据短公告的
20秒局部速度承诺整批完成时间。

推荐顺序：

1. 行情/财务与正文按数据源独立推进，先消除验证等待。日线已提前启动；
   财务尚未启动，仍按原队列继续。
2. 对长公告测试“一次PDF下载+本地抽取”，与已归档分页正文核对身份、
   页完整性、关键数值及扫描件比例。验证前不把它作为已证实的提速通道。
3. 正文逐页保存断点，长文末页失败时只重试缺页。现实现的页列表仅保存在
   单次调用内，跨进程不能恢复已成功获取的前页。
4. 将外层无限批次循环改为有界恢复和网络健康检查；连续3次失败的内层
   熔断会被外层while循环再次启动，因而出现47轮重复尝试。
5. 暂不增加浏览器worker或提高源站请求速率。此前已有429/567及DoH/TLS失败
   证据，增加并发未必增加有效归档量，还会增加本机资源使用。

## 已实现的轻量端到端入口

```powershell
.venv\Scripts\python.exe scripts\validate_pilot_end_to_end.py `
  --output data/validation/event_ranking_pilot_electrical_v1/e2e_NEW_RUN
```

输出目录必须是新目录，避免覆盖上一轮证据。入口只读数据库，SQL只选择
2023—2024公告及截至2024年底的日线，先在本地分开保存特征与标签。

流程为：真实公告/日线 → 公司与入场日聚合 → 1/3/5日标签 → 三路轻量模型 →
3个扩展时间折OOF → 等权融合、非负静态融合、移除单专家对照 → 日内排名与评估。
非负融合只使用更早时间折、且收益已经到期的OOF；所有模型、分词词表和
标准化均仅用各折训练数据拟合。排序文件先落盘并保存哈希，再评估。
同一股票多个公告日期落在相同入场日时合并，避免重复排名。

三路模型明确是工程验证用基线：标题字符TF-IDF+Ridge、公告类别与滞后行情
Ridge、20个滞后日收益序列Ridge。它们不是已验收的LLM、PIT表格专家或LSTM。
执行限制数值线程为1。比较使用相同样本，仅在候选数大于5的日期评估Top-5
与其余股票的收益差，避免把空余集计算成有效比较。

首轮真实数据运行e2e_20260905_02已完成：48只股票、487个公司日、1,455个
特征/标签样本、1,076条OOF、706个共同对照样本。该次行情下载尚未完成，
属于接线验证；不能将其收益指标宣称为板块有效性或正式模型通过。
