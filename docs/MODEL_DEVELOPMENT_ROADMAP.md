# 多模型公告预测路线图

最后更新：2026-08-21

这份文档是后续逐步实施的唯一主路线图。每完成一个阶段，都要更新状态、证据、模型版本和放行结论。任何模块未通过本阶段门槛，不得提前进入正式测试或每日利多榜。

## 永久数据边界

- 训练集：2023-01-01 至 2024-12-31。
- 一次性官方测试集：2025-01-01 至 2025-08-19。
- 隔离集：2025-08-20 至 2025-12-31；旧模型曾使用，不能重新命名为盲测。
- 前向验证集：2026-01-01 起；只验证，不训练、不调参。
- 官方测试集目前读取次数：**0**。
- 禁止随机切分。训练集内部只能做按时间向前推进的 expanding-window 验证。

## 当前默认决策时点

第一套系统固定为每日开盘前运行，逻辑时点为 Asia/Shanghai 08:30。历史数据暂时只有公告日期、没有可靠分钟级发布时间，因此历史回放采用最保守规则：

- 可以读取当时已经发布的公告原文；
- 行情只能读取 `trade_date < announcement.published_date` 的记录；
- 财务数据必须在预测时点以前已经披露，禁止使用后来更正或重述的数据；
- Memory 只能读取 `outcome_available_at <= prediction.as_of` 的历史结果；
- 当前大模型在历史阶段只能做带原文证据的客观提取，不能把自身已有知识当成历史涨跌标签。

未来如果补齐可靠的公告发布时间，可以建立新的合同版本；不得静默修改本合同。

首次覆盖率审计结果：

- 训练集 89,485 条公告，正文和 PDF 覆盖均为 0。
- 官方测试集 29,504 条公告，正文和 PDF 覆盖均为 0；未读取任何涨跌标签。
- 全库 165,898 条公告中，163,537 条原始元数据包含可解析的 `eiTime` 候选时间。
- `eiTime` 仍只是候选来源时间，尚未证明等同于交易所正式发布时间，因此暂不写入正式时间字段。
- 发现 192 组“同公司、同日期、同标题”重复候选，需要在正文回填前确认是多证券映射、重复抓取还是公告版本差异。
- 对训练期按时间均匀抽取的 12 条公告进行了只读正文接口探测，12/12 返回正文和附件地址；数据库未被修改。这说明历史正文具备回填可行性，但尚未证明归档内容永远不变。
- 深度核验发现 `page_size` 实际为正文页数，旧代码只取第一页。17页和45页样本此前均被截断为5,000字符，修复后分别恢复为84,652和224,498字符。
- 12条深度样本的完整分页、公告身份、列表/正文候选时间一致性和PDF格式验证均为12/12。
- 48条候选时间样本中，列表接口与正文接口的 `eiTime`、公告编号日期、标题和 `notice_date` 均为48/48一致；其中37条为 `notice_date` 前一日晚间。
- 附件URL时间参数按标准Unix时间解释时与 `eiTime` 中位相差约8小时，存在明确时区编码歧义。因此 `eiTime` 只能归档为来源候选时间，不能宣称为交易所权威发布时间。
- “前一日晚间发布、下一日记为 notice_date”的模式提示旧版按 `published_date` 后下一开盘执行的目标可能晚一个交易日。该目标暂不修改；只有建立版本化时间合同后才能生成独立的 timing-v2 研究目标。
- 已建立 `announcement_source_archives` 追加式归档表：相同快照幂等，内容变化追加新版本，禁止更新和删除旧版本。
- 已建立逐条原子状态的可恢复回填脚本。首批70条普通训练正文、55条核心队列新增正文和2条PDF深度归档均为0失败。
- 训练期高置信公告共72,002条，其中核心事件32,668条、支持性文档27,466条、例行披露11,868条。当前先回填核心事件，避免低价值文档阻塞文本模型。
- 核心事件后台回填已经启动，运行和恢复说明见 `docs/SOURCE_ARCHIVE_RUNBOOK.md`。本阶段在该任务完成并通过覆盖率复核前保持进行中。
