## 为什么尚未放行

行业接口的当前记录与历史记录能覆盖大部分训练日期，但仍有61个代码在部分公告日没有任何有效区间，主要集中在2023年申万分类纳入日之前。用今天的 `stock_basic.industry` 回填这些日期会制造前视，因此审计选择缺失并阻断，而不是猜测。

财务接口提供 `ann_date`、实际披露日 `f_ann_date`、报告类型和 `update_flag`，足以建立候选时点链；但本次是在2026年读取供应商当前数据库快照。仅凭当前响应不能证明历史更正发生后，供应商没有把更正值覆盖到旧版本记录。这个问题与大模型无关，需要供应商语义证据或历史公告原表交叉核验。

## 建议后续路径（待用户确认）

1. 先完成行业缺口补齐。优先查找同一申万版本的历史成分来源；结构化接口不足时，可用CDP归档公开网页或下载文件。只接受带生效/失效日期的记录，无法证明的900个公司日继续保留缺失。
2. 同时完成财务修订语义验收。按年度、季度、修订组和公司分层抽样，将API返回版本与当时公告PDF/结构化原表交叉核对；CDP可负责抓取和归档，数值核对可用确定性表格解析，不需要等待大模型。
3. 两个组分别放行，不互相捆绑。先为通过的组建立新的 `tabular_feature_catalog_v3` 和 `train_v3`，增加明确的缺失/拒判标志；不改写v2。
4. 在同一批样本、相同fold和相同模型参数下，分别做“公司/行业”和“时点财务”消融，再重跑统一OOF。没有稳定增量就保留审计证据但不冻结模型。
5. 结构化公告事实继续等待大模型事实抽取独立通过；它不阻塞前四步。

CDP在这里是补充采集和留证手段，不是时间正确性的自动证明。真正的放行依据仍是有效日期、实际披露日期、版本链、内容哈希和训练样本日期联接审计。

本节覆盖本报告前述初始快照之后的补充审计；初始报告中的94.71%/900/61是补充前数字，不再作为当前行业覆盖结论。

- 补充选择采用有明确 `in_date/out_date` 的历史成员记录，不把 `stock_basic.industry` 当前快照倒灌到历史。补充后覆盖16,204/17,017公司日（95.2224%），相对初始快照新增87个公司日；仍缺813个公司日、58个代码，歧义0，不能进入正式特征。
- 补充与原申万来源的可比较日期15,545个，标签一致15,545个、冲突0。机器报告：`data/tabular/industry_supplement_v1/audit.report.json`。
- 财务修订目录：`data/tabular/financial_revision_evidence_v1/`。训练期抽样12个修订组、17份公告PDF；16份PDF正文可抽取并完成逐版本哈希/标题/数值审计，9/12修订组通过，income/balancesheet/cashflow分别3/3/3，超过最低8组且每端点最低2组。

当前放行结论：行业仍因813个缺失公司日阻断；财务因1份全扫描PDF正文证据未解决而阻断。两组都可以在不等待大模型的情况下继续补采，但不能把当前快照或CDP标题元数据直接写入`train_v2`。
